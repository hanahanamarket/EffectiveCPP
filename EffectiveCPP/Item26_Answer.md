# 模範解答

## (1) 正解：A

### この問題で確認したいこと

変数の定義は可能な限り先延ばしする。

### 解説

`encrypted` は例外が発生した場合には使用されない。

しかし現在のコードは関数の先頭で

```cpp
std::string encrypted;
```

とデフォルト構築したあと、例外チェックを経て

```cpp
encrypted = password;
```

と代入している。`std::string encrypted;` の時点ですでにオブジェクト生成コストが発生する。

そのため、

```cpp
if (password.length() < 8)
{
    throw std::logic_error("too short");
}

std::string encrypted(password);
```

のように、本当に必要になった時点で生成する方が望ましい。

|選択肢|判定|理由|
|-------|-------|-------|
|A|○|不要なオブジェクト生成を防げる|
|B|×|return文の必要性は変わらない|
|C|×|例外発生条件は変わらない|
|D|×|コピーコンストラクタ呼び出しとは無関係|

## (2) 正解：B

### この問題で確認したいこと

代入より初期化を優先する。

### 解説

コードAは

```cpp
Widget w;
w = 10;
```

であり、

1. `Widget()` によるデフォルト構築
2. `operator=(int)` による代入

の2段階を実行する。

一方コードBは

```cpp
Widget w(10);
```

であり、

1. `Widget(int)` による構築

だけで目的の状態を作る。

そのため余分な処理が発生しない。

|選択肢|判定|理由|
|-------|-------|-------|
|A|×|デストラクタは呼ばれる|
|B|○|`Widget(int)` による直接初期化で、デフォルト構築と代入を避けられる|
|C|×|オブジェクト生成は行われる|
|D|×|スコープの話ではない|

## (3) 正解：A

### この問題で確認したいこと

代入がコピー構築＋破棄よりずっと安い場合、ループ外で1つだけ `Widget` を再利用する判断ができるか。

### 解説

方法Aは

```cpp
Widget w;              // デフォルト構築 1 回

for (int i = 0; i < n; ++i)
{
    w = makeWidget(i); // 代入 n 回（makeWidget の戻り値は一時オブジェクト）
}
// 破棄 1 回
```

方法Bは

```cpp
for (int i = 0; i < n; ++i)
{
    Widget w(makeWidget(i)); // コピー構築 n 回
}                            // 各反復で破棄 n 回
```

問題文の前提どおり、1回の代入は「1回のコピー構築＋1回の破棄」よりずっと小さいコストである。

`n` が大きいとき、方法Bは反復のたびにコピー構築と破棄を繰り返すのに対し、方法Aはデフォルト構築1回・破棄1回と代入 `n` 回にとどまる。

したがって、この問題文のコスト条件下では性能面から方法Aが適切である。

なお、変数の有効範囲を狭く保てる方法Bには可読性・保守性の利点がある。Item 26 の基本方針は使用箇所の近くで定義することだが、本問のようにコスト差が明示されている場合は性能上の例外としてループ外再利用を選べる。

|選択肢|判定|理由|
|-------|-------|-------|
|A|○|代入コストが小さい前提で、コピー構築・破棄回数を抑えられる|
|B|×|有効範囲の狭さは性能面の理由ではない|
|C|×|方法Aは反復ごとのコピー構築・破棄を避けられる|
|D|×|方法Bでも各反復で `makeWidget` の結果を受け取るため、デフォルト構築省略の意味では優れない|
