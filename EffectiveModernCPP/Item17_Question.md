# 設問

C++11 のクラスには、条件を満たすとコンパイラが用意する特殊メンバ関数が6つある。デフォルトコンストラクタ、デストラクタ、コピーコンストラクタ、コピー代入演算子、ムーブコンストラクタ、ムーブ代入演算子である。どの関数をユーザがクラス定義に書いたかで、残りの関数が呼び出せるか、宣言されないか、delete されるかが決まる。

各問は独立している。コードは C++11 の規則で判定し、必要なヘッダはインクルード済みとする。コンパイラの最適化は考えない。警告が出ても、規則上呼び出せる関数は呼び出せるものとする。

このファイルでは次を共通の規則とする。

- ユーザ宣言とは、その関数の宣言をクラス定義の中に書くことである。関数本体をその場に書く宣言、`= default`、`= delete` は、いずれもユーザ宣言である
- 宣言されていない関数は、オーバーロード解決の候補にならない
- delete された関数は候補になる。選ばれた関数が delete なら、その呼び出しは不適格である
- `std::move(x)` は `x` を右辺値参照へキャストするだけであり、このキャスト自体はメンバをムーブしない
- 各クラスに、コードへ書いた以外の基底、メンバ、関数宣言は無い。参照メンバや const メンバは無い
- コピーが呼ばれたあと、コピー元の `std::string` と `std::map` は変化しない。このファイルでは、ムーブが呼ばれたあと、ムーブ元は空になると決める

---

## (1)

`Widget` がユーザ宣言している特殊メンバ関数は、次のコピーコンストラクタだけである。その定義は `name` をコピーする。

```cpp
class Widget {
public:
    Widget(const Widget& rhs);
private:
    std::string name;
};
```

この問では次を仮定する。

- 判定するのは下の初期化だけである。`a` は構築済みで、`a.name` は `"widget"` である
- ムーブコンストラクタが候補に無いとき、この右辺値は `const Widget&` に束縛でき、上のコピーコンストラクタを呼べる
- ムーブコンストラクタと上のコピーコンストラクタの両方が候補のとき、この右辺値にはムーブコンストラクタの方が適合が良い
- ムーブコンストラクタが呼ばれた場合、その定義は `name` をムーブする

```cpp
Widget b(std::move(a));
```

この初期化の結果として最も適切なものはどれか。

A. 適格である。生成されたムーブコンストラクタが呼ばれ、`a.name` は空、`b.name` は `"widget"` になる

B. 適格である。ユーザ宣言のコピーコンストラクタが呼ばれ、`a.name` も `b.name` も `"widget"` のままである

C. 不適格である。ムーブコンストラクタが delete として宣言され、その関数がコピーコンストラクタより優先して選ばれる

D. 不適格である。コピーコンストラクタをユーザ宣言したクラスにはデフォルトコンストラクタが無く、引数のあるこの初期化もできない

## (2)

`Widget` がユーザ宣言している特殊メンバ関数は、次のコピーコンストラクタだけである。`a` と `b` は構築済みである。代入の前、`a.name` は `"src"` であり、`b.name` は `"src"` ではない。

```cpp
class Widget {
public:
    Widget(const Widget& rhs);
private:
    std::string name;
};
```

この問では次を仮定する。

- 各文の適格性は独立に判定する
- 代入がどの代入演算子を呼ぶかは、代入演算子のオーバーロード解決だけで決まる
- コピー代入演算子が候補にあり、ムーブ代入演算子が候補に無いとき、右辺値はそのコピー代入演算子の `const Widget&` に束縛できる
- コピー代入演算子とムーブ代入演算子の両方が候補で、実引数が右辺値のときは、ムーブ代入演算子の方が適合が良い
- 呼び出せるコピー代入演算子は、`name` をコピーする
- 呼び出せるムーブ代入演算子は、`name` をムーブする

```cpp
b = a;             // 文1
b = std::move(a);  // 文2
```

文1と文2の結果として最も適切なものはどれか。

A. 文1は適格で、`b.name` は `"src"` になる。文2は不適格である

B. 文1は不適格である。文2は適格で、ムーブ代入演算子が呼ばれ、`a.name` は空、`b.name` は `"src"` になる

C. 文1も文2も適格である。どちらもムーブ代入演算子が呼ばれ、`a.name` は空、`b.name` は `"src"` になる

D. 文1も文2も適格である。どちらもコピー代入演算子が呼ばれ、`a.name` は `"src"` のまま、`b.name` は `"src"` になる

## (3)

`Widget` がユーザ宣言している特殊メンバ関数は、デフォルトコンストラクタとムーブコンストラクタだけである。ムーブコンストラクタの定義は `name` をムーブする。

```cpp
class Widget {
public:
    Widget() {}
    Widget(Widget&& rhs);
private:
    std::string name;
};

Widget a;
Widget b;
b = a;             // 文1
b = std::move(a);  // 文2
```

この問では次を仮定する。

- 各文の適格性は独立に判定する
- 代入がどの代入演算子を呼ぶかは、代入演算子のオーバーロード解決だけで決まる
- `std::string` のコピーとムーブは可能であり、`name` を理由に代入演算子が delete されることはない
- コピー代入演算子が delete で、ムーブ代入演算子が候補に無いとき、左辺値の代入も右辺値の代入も、その delete されたコピー代入演算子が候補になる

文1と文2の結果として最も適切なものはどれか。

A. 文1も文2も不適格である

B. 文1も文2も適格である。文1はコピー代入演算子、文2はムーブ代入演算子を呼ぶ

C. 文1は不適格である。文2は適格で、ムーブ代入演算子を呼ぶ

D. 文1は適格で、コピー代入演算子を呼ぶ。文2は不適格である

## (4)

追加前の `StringTable` は次のとおりである。この問では、追加前の `StringTable b(std::move(a));` がムーブコンストラクタを呼び、`values` をムーブすることを前提とする。

```cpp
class StringTable {
public:
    StringTable();
private:
    std::map<int, std::string> values;
};
```

追加後は、ログ用のデストラクタだけをユーザ宣言する。このデストラクタの定義はログを1行出すだけで、`values` を変更しない。`std::map<int, std::string>` のコピーコンストラクタとムーブコンストラクタは存在し、delete されていない。

```cpp
class StringTable {
public:
    StringTable();
    ~StringTable();
private:
    std::map<int, std::string> values;
};
```

この問では次を仮定する。

- 判定するのは、追加後のクラスによる次の初期化だけである。`a` は構築済みである
- ムーブコンストラクタが候補に無いとき、この右辺値はコピーコンストラクタの `const StringTable&` に束縛できる
- ムーブコンストラクタとコピーコンストラクタの両方が候補のとき、この右辺値にはムーブコンストラクタの方が適合が良い
- コピーコンストラクタが呼ばれたとき、`values` はコピーされる
- ムーブコンストラクタが呼ばれたとき、`values` はムーブされる

```cpp
StringTable b(std::move(a));
```

追加後のこの初期化として最も適切なものはどれか。

A. 追加前と同じく、ムーブコンストラクタが呼ばれ、`values` はムーブされる

B. 不適格である。デストラクタをユーザ宣言すると、コピーコンストラクタは delete される

C. コピーコンストラクタが呼ばれ、`values` はコピーされる。ムーブコンストラクタは宣言されない

D. ムーブコンストラクタが呼ばれ、`values` はムーブされる。コピーコンストラクタは delete される

## (5)

`Base` のデストラクタは virtual でなければならない。`name` のコピーとムーブは、どちらも可能である。

```cpp
class Base {
public:
    virtual ~Base() = default;
private:
    std::string name;
};
```

このクラスを変更し、次の3つを同時に満たしたい。

1. デストラクタは virtual のままである
2. コピーコンストラクタとコピー代入演算子を呼べる。呼ぶと `name` はコピーされる
3. ムーブコンストラクタとムーブ代入演算子を呼べる。呼ぶと `name` はムーブされる

この問では次を仮定する。

- デフォルトコンストラクタが生成されるかは、正誤に影響しない
- 右辺値をコピーコンストラクタやコピー代入演算子で受けることは、要件3を満たさない
- クラス定義に `= default` と書いたコピー操作やムーブ操作は、`name` を理由に delete されない。同じクラスでムーブ操作も `= default` にしていても、`= default` と書いたコピー操作は delete されない
- `= default` のコピー操作が呼ばれると `name` はコピーされ、`= default` のムーブ操作が呼ばれると `name` はムーブされる

最も適切な変更はどれか。

A. 宣言を追加しない

B. 次の4つを追加する

```cpp
Base(const Base&) = default;
Base& operator=(const Base&) = default;
Base(Base&&) = default;
Base& operator=(Base&&) = default;
```

C. 次の2つを追加する

```cpp
Base(Base&&) = default;
Base& operator=(Base&&) = default;
```

D. 次の2つを追加する

```cpp
Base(const Base&) = default;
Base& operator=(const Base&) = default;
```
