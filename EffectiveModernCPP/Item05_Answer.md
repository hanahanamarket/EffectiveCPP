# 模範解答

## (1) 正解：**D**

#### この問題で確認したいこと

ラムダ式を `auto` で受けるとクロージャ型そのものになり、`std::function` で受けると別の型になってヒープ確保と間接呼び出しが起きることを確認する。

#### 解説

クロージャ型にはソースに書ける名前がない。`f` は `auto` なので、初期化子のラムダ式のクロージャ型になる。この初期化は `std::function` を作らないため、仮定どおりヒープを確保しない。

`g` の型は宣言どおり `std::function<int(int)>` である。同じ呼び出しはできるが、クロージャ型ではない。仮定ではこのクロージャは内部バッファに収まらないので、`g` の初期化はヒープを確保する。呼び出しは `std::function` を経由する間接呼び出しになる。この実行では確保が成功するので、`g` の初期化は完了する。

|選択肢|判定|理由|
|-------|-------|-------|
|A|×|`g` はクロージャ型ではなく `std::function<int(int)>` であり、ヒープ確保と間接呼び出しが起きる|
|B|×|ヒープを確保するのは `std::function` である `g` の側である|
|C|×|仮定では、ヒープ確保に失敗したときだけ `std::bad_alloc` になり、この実行では確保が成功する|
|D|○|`f` はクロージャ型のまま保持し、`g` は型消去した `std::function` としてヒープ確保と間接呼び出しを行う|

## (2) 正解：**A**

#### この問題で確認したいこと

`size()` の戻り値を幅の違う `unsigned` で受けると値が変換され、`auto` は戻り値の型と値を保つことを確認する。

#### 解説

この処理系では `v.size()` の型は 64ビット符号なし整数で、値は 4294967296 である。`unsigned` は 32ビットなので、`sz` の初期化では 4294967296 で割った余り、すなわち 0 になる。この変換は暗黙に行われ、`sz` の宣言は適格である。

`n` は `auto` なので、初期化子を `unsigned` へ変換しない。型は `size()` の戻り値の型のまま、値は 4294967296 のままである。

|選択肢|判定|理由|
|-------|-------|-------|
|A|○|`sz` は 32ビットへ変換されて 0 になり、`n` は `size()` の戻り値の型と値を保つ|
|B|×|この初期化は `=` によるもので、幅が違っても適格であり、変換が行われる|
|C|×|`auto` は初期化子の型を使うので、`n` は `unsigned` にはならない|
|D|×|`unsigned` へ変換された `sz` の値は 0 であり、`n` と同じ型でもない|

## (3) 正解：**C**

#### この問題で確認したいこと

マップの要素型と違う `pair` の参照は一時オブジェクトに束縛され、`const auto&` は要素そのものを参照することを確認する。

#### 解説

`m` の要素型は `std::pair<const std::string, int>` であり、キーは `const` である。`p` の型 `std::pair<std::string, int>` は要素型と違う。仮定の変換コンストラクタがキーの文字列をコピーして一時オブジェクトを作り、`p` はその一時オブジェクトに束縛される。`p` は `m` の要素そのものではない。

`q` は `const auto&` なので、要素型 `std::pair<const std::string, int>` への const 参照になる。変換は行われず、`q` は要素そのものを参照する。

|選択肢|判定|理由|
|-------|-------|-------|
|A|×|`p` の型は要素型と違うので、要素ではなく一時オブジェクトに束縛される|
|B|×|一時オブジェクトに束縛されるのは `p` であり、`q` は要素そのものを参照する|
|C|○|`p` はキーをコピーした一時オブジェクトを参照し、`q` は要素そのものを参照する|
|D|×|変換コンストラクタにより `p` の初期化は適格である|

## (4) 正解：**B**

#### この問題で確認したいこと

戻り値の型が変わって再コンパイルしたとき、明示した変数の型は変わらず、`auto` の変数は宣言を書き換えずに新しい型になることを確認する。

#### 解説

`x` の宣言は `int` のままなので、再コンパイル後も `x` の型は `int` である。変更後の戻り値 `long` は、仮定どおり `int` へ暗黙変換されて `x` を初期化する。この宣言は適格である。

`y` は `auto` なので、そのコンパイルにおける初期化子の型、すなわち変更後の `long` になる。`y` の宣言を `long y` に書き換えなくても、再コンパイルだけで型は `long` になる。

|選択肢|判定|理由|
|-------|-------|-------|
|A|×|`x` は `int` と宣言されているので、再コンパイルしても `long` にはならない|
|B|○|`x` は `int` のまま変換され、`y` は宣言を書き換えずに `long` になる|
|C|×|`auto` は再コンパイルのたびに初期化子から型を決めるので、`y` は `long` になる|
|D|×|`long` から `int` への変換があり、`x` も `y` もこの仮定の下では適格である|
