# 模範解答

## (1) 正解：**B**

#### この問題で確認したいこと

コピーコンストラクタだけをユーザ宣言するとムーブコンストラクタは宣言されず、右辺値からの初期化はコピーになることを確認する。

あわせて、コピーコンストラクタを宣言してもコピー代入演算子は生成され、右辺値の代入もそのコピー代入になることを確認する。

#### 解説

コピーコンストラクタをユーザ宣言したクラスでは、ムーブコンストラクタは暗黙に宣言されない。delete としても宣言されない。候補に無いので、`Widget b(std::move(a));` の右辺値はユーザ宣言のコピーコンストラクタの `const Widget&` に束縛される。その定義は `name` をコピーするため、`a.name` も `b.name` も `"widget"` のままである。

コピーコンストラクタとコピー代入演算子は別々に決まる。コピーコンストラクタをユーザ宣言しても、コピー代入演算子は暗黙に宣言され、`name` をコピーする定義になる。この暗黙のコピー代入は C++11 では非推奨だが、delete ではなく呼び出せる。ムーブ代入演算子は、コピーコンストラクタがユーザ宣言されているため暗黙に宣言されない。候補にならないので、`c = std::move(a);` の右辺値はコピー代入演算子の `const Widget&` に束縛される。したがって `a.name` は `"widget"` のまま、`c.name` は `"widget"` になる。

|選択肢|判定|理由|
|-------|-------|-------|
|A|×|ムーブコンストラクタもムーブ代入演算子も生成されない。右辺値でも呼ばれるのはコピーである|
|B|○|初期化はコピーコンストラクタ、代入はコピー代入演算子であり、`a.name` は空にならない|
|C|×|コピー代入演算子は生成される。右辺値の代入もそのコピー代入でコンパイルできる|
|D|×|ムーブ演算の生成が抑制され、暗黙に宣言されない。delete にもならないので候補に入らない|

## (2) 正解：**A**

#### この問題で確認したいこと

ムーブコンストラクタをユーザ宣言すると、コピー代入は delete され、ムーブ代入は宣言されず、左辺値の代入も右辺値の代入もコンパイルエラーとなることを確認する。

#### 解説

ムーブコンストラクタをユーザ宣言すると、ムーブ代入演算子は暗黙に宣言されない。コピー代入演算子は暗黙に宣言されるが、ムーブコンストラクタの宣言が原因で delete になる。`name` がムーブできることは、この delete を妨げない。

文1では、delete されたコピー代入演算子が `a` の候補になる。文2では、ムーブ代入演算子が候補に無いので、同じ delete されたコピー代入演算子が右辺値の候補になる。どちらの文も、選ばれた関数が delete なのでコンパイルエラーとなる。

|選択肢|判定|理由|
|-------|-------|-------|
|A|○|コピー代入は delete され、ムーブ代入は宣言されない。文1も文2もコンパイルエラーとなる|
|B|×|呼び出せるコピー代入もムーブ代入も無い|
|C|×|ムーブ代入演算子は、ムーブコンストラクタを宣言したクラスでは生成されない|
|D|×|コピー代入演算子は暗黙に宣言されるが delete であり、文1はコンパイルできるようにはならない|

## (3) 正解：**C**

#### この問題で確認したいこと

ログのためだけにデストラクタをユーザ宣言するとムーブコンストラクタが宣言されなくなり、同じ初期化がコピーになることを確認する。

#### 解説

デストラクタを加える前は、前提どおりムーブコンストラクタが呼ばれる。加えたあとはデストラクタがユーザ宣言になる。デストラクタの本体が `values` を変えなくても、ユーザ宣言であること自体でムーブコンストラクタは暗黙に宣言されない。

コピーコンストラクタは暗黙に宣言され、delete にはならない。C++11 ではこの暗黙のコピーは非推奨だが、仮定どおり呼び出せる。ムーブコンストラクタが候補に無いので、右辺値はコピーコンストラクタに束縛され、`values` はコピーされる。

|選択肢|判定|理由|
|-------|-------|-------|
|A|×|デストラクタが `values` を変更しなくても、デストラクタのユーザ宣言でムーブコンストラクタは宣言されなくなる|
|B|×|デストラクタのユーザ宣言は、コピーコンストラクタを delete にしない|
|C|○|ムーブコンストラクタは宣言されず、暗黙のコピーコンストラクタが `values` をコピーする|
|D|×|コピーコンストラクタは delete にならず、ムーブコンストラクタは生成されない|

## (4) 正解：**B**

#### この問題で確認したいこと

virtual なデストラクタを残したまま、メンバごとのコピーとメンバごとのムーブの両方を使うには、コピー演算とムーブ演算の4つ(コンストラクタと代入演算子の2つ × コピーとムーブの2つ)も `= default` にすることを確認する。

#### 解説

`virtual ~Document() = default` はユーザ宣言なので、ムーブは暗黙に宣言されない。右辺値をコピーで受けることは、問題が求めるムーブではない。

C（ムーブだけ）だと、書いていないコピーは delete になり、退避用のコピーがコンパイルエラーとなる。D（コピーだけ）だとムーブは宣言されず、送信キューへの受け渡しはコピーになる。B（4つとも `= default`）なら、仮定どおりどれも delete にならず、デストラクタも virtual のままである。

|選択肢|判定|理由|
|-------|-------|-------|
|A|×|デストラクタのユーザ宣言で、ムーブは暗黙に宣言されない|
|B|○|virtual デストラクタを残し、コピー2つとムーブ2つを `= default` する|
|C|×|ムーブのユーザ宣言で、書いていないコピーは delete になる|
|D|×|デストラクタとコピーのユーザ宣言で、ムーブは暗黙に宣言されない|
