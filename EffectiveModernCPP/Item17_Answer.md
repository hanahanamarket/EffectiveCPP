# 模範解答

## (1) 正解：**B**

#### この問題で確認したいこと

コピーコンストラクタだけをユーザ宣言するとムーブコンストラクタは宣言されず、右辺値からの初期化はコピーになることを確認する。

#### 解説

コピーコンストラクタをユーザ宣言したクラスでは、ムーブコンストラクタは暗黙に宣言されない。delete としても宣言されない。候補に無いので、`std::move(a)` の右辺値はユーザ宣言のコピーコンストラクタの `const Widget&` に束縛される。その定義は `name` をコピーするため、`a.name` も `b.name` も `"widget"` のままである。

|選択肢|判定|理由|
|-------|-------|-------|
|A|×|ムーブコンストラクタは生成されない。右辺値でも、呼ばれるのはコピーコンストラクタである|
|B|○|ムーブコンストラクタは候補にならず、ユーザ宣言のコピーコンストラクタが `name` をコピーする|
|C|×|このクラスのムーブコンストラクタは delete ではなく、宣言自体が無い。候補にならない|
|D|×|デフォルトコンストラクタが無いことは、既存の `a` からコピーコンストラクタで `b` を初期化することを妨げない|

## (2) 正解：**D**

#### この問題で確認したいこと

コピーコンストラクタを宣言してもコピー代入演算子は生成され、右辺値の代入もそのコピー代入になることを確認する。

#### 解説

コピーコンストラクタとコピー代入演算子は別々に決まる。コピーコンストラクタをユーザ宣言しても、コピー代入演算子は暗黙に宣言され、`name` をコピーする定義になる。この暗黙のコピー代入は C++11 では非推奨だが、delete ではなく、仮定どおり呼び出せる。

ムーブ代入演算子は、コピーコンストラクタがユーザ宣言されているため暗黙に宣言されない。候補にならないので、文2の右辺値はコピー代入演算子の `const Widget&` に束縛される。文1も文2もコピー代入であり、`a.name` は `"src"` のまま、`b.name` は `"src"` になる。

|選択肢|判定|理由|
|-------|-------|-------|
|A|×|文2のムーブ代入演算子は delete されているのではなく、宣言されていない。右辺値はコピー代入できる|
|B|×|コピー代入演算子は生成される。文2で呼ばれるのもコピー代入であり、`a.name` は空にならない|
|C|×|ムーブ代入演算子は生成されない。文1の左辺値からも文2の右辺値からもコピー代入が呼ばれる|
|D|○|二つの代入はどちらもコピー代入演算子を呼び、コピー元の `name` は `"src"` のまま残る|

## (3) 正解：**A**

#### この問題で確認したいこと

ムーブコンストラクタをユーザ宣言すると、コピー代入は delete され、ムーブ代入は宣言されず、左辺値の代入も右辺値の代入も不適格になることを確認する。

#### 解説

ムーブコンストラクタをユーザ宣言すると、ムーブ代入演算子は暗黙に宣言されない。コピー代入演算子は暗黙に宣言されるが、ムーブコンストラクタの宣言が原因で delete になる。`name` がムーブできることは、この delete を妨げない。

文1では、delete されたコピー代入演算子が `a` の候補になる。文2では、ムーブ代入演算子が候補に無いので、同じ delete されたコピー代入演算子が右辺値の候補になる。どちらの文も、選ばれた関数が delete なので不適格である。

|選択肢|判定|理由|
|-------|-------|-------|
|A|○|コピー代入は delete され、ムーブ代入は宣言されない。文1も文2も不適格である|
|B|×|呼び出せるコピー代入もムーブ代入も無い|
|C|×|ムーブ代入演算子は、ムーブコンストラクタを宣言したクラスでは生成されない|
|D|×|コピー代入演算子は暗黙に宣言されるが delete であり、文1は適格にならない|

## (4) 正解：**C**

#### この問題で確認したいこと

ログのためだけにデストラクタをユーザ宣言するとムーブコンストラクタが宣言されなくなり、同じ初期化がコピーになることを確認する。

#### 解説

追加前は、前提どおりムーブコンストラクタが呼ばれる。追加後はデストラクタがユーザ宣言になる。デストラクタの本体が `values` を変えなくても、ユーザ宣言であること自体でムーブコンストラクタは暗黙に宣言されない。

コピーコンストラクタは暗黙に宣言され、delete にはならない。C++11 ではこの暗黙のコピーは非推奨だが、仮定どおり呼び出せる。ムーブコンストラクタが候補に無いので、右辺値はコピーコンストラクタに束縛され、`values` はコピーされる。

|選択肢|判定|理由|
|-------|-------|-------|
|A|×|デストラクタが `values` を変更しなくても、デストラクタのユーザ宣言でムーブコンストラクタは宣言されなくなる|
|B|×|デストラクタのユーザ宣言は、コピーコンストラクタを delete にしない|
|C|○|ムーブコンストラクタは宣言されず、暗黙のコピーコンストラクタが `values` をコピーする|
|D|×|コピーコンストラクタは delete にならず、ムーブコンストラクタは生成されない|

## (5) 正解：**B**

#### この問題で確認したいこと

virtual なデストラクタを残したまま、メンバごとのコピーとメンバごとのムーブの両方を使うには、4つのコピー操作とムーブ操作も `= default` にすることを確認する。

#### 解説

`virtual ~Base() = default` はデストラクタのユーザ宣言である。このままではムーブコンストラクタとムーブ代入演算子は暗黙に宣言されない。右辺値をコピーで受けることは、要件3のムーブではない。

ムーブの2つだけを `= default` にすると、その2つはユーザ宣言になる。クラス定義に書いていないコピー操作は暗黙に宣言され、ムーブ操作をユーザ宣言したことが原因で delete になる。要件2を満たさない。

コピーの2つだけを `= default` にすると、コピーはできる。一方でデストラクタとコピー操作がユーザ宣言なので、ムーブ操作は暗黙に宣言されない。要件3を満たさない。

4つとも `= default` にすると、コピー操作とムーブ操作はどれもユーザが宣言した `= default` である。仮定どおり、ムーブを `= default` にしていても、一緒に書いたコピーの `= default` は delete されない。デストラクタは virtual のままである。要件1、2、3を同時に満たす。

|選択肢|判定|理由|
|-------|-------|-------|
|A|×|デストラクタの `= default` はユーザ宣言なので、ムーブ操作は暗黙に宣言されない|
|B|○|virtual なデストラクタを残し、コピー2つとムーブ2つを、delete されない `= default` として宣言する|
|C|×|ムーブ操作のユーザ宣言により、書いていないコピー操作は delete になる|
|D|×|デストラクタとコピー操作がユーザ宣言なので、ムーブ操作は暗黙に宣言されない|
