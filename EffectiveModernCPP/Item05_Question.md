# 設問

型を明示する理由がなければ `auto` を使う。`auto` の型は初期化子の式から決まるため初期化子が必須であり、未初期化の変数、長い型名の手書き、手で書いた型への意図しない変換を避けられる。

各問は独立している。コードは C++11 の規則で判定し、必要なヘッダはインクルード済みとする。処理系や最適化に依存する点は、各問の仮定に従う。

---

## (1)

ラムダ式は、式ごとに固有のクロージャ型のオブジェクトを作る。そのクロージャ型を指す名前をプログラマがソースに書くことはできない。

`std::function<int(int)>` は、`int` を受け取り `int` を返す呼び出し可能オブジェクトを、クロージャ型とは別の型として保持する。

この問では次を仮定する。

- 下の2つのラムダ式のクロージャは、どちらも `std::function` の内部バッファに収まらない
- 収まらないとき、`std::function` はヒープを確保する。確保に失敗したときだけ `std::bad_alloc` を送出する
- `std::function` を経由した呼び出しは間接呼び出しになる
- `auto` で宣言した変数の型はクロージャ型そのものであり、その初期化ではヒープを確保しない
- コンパイラの最適化は考えない
- この問の実行ではヒープ確保は成功する

```cpp
auto f = [](int x) { return x + 1; };
std::function<int(int)> g = [](int x) { return x + 1; };
```

この仮定の下で最も適切なものはどれか。

A. `f` と `g` は同じクロージャ型であり、ヒープ確保の有無も呼び出し方法も同じである

B. `f` の型は `std::function<int(int)>` でヒープを確保する。`g` の型はクロージャ型で、ヒープを確保しない

C. `g` の初期化はヒープを使うため必ず `std::bad_alloc` になり、使えるのは `f` だけである

D. `f` の型はクロージャ型で、初期化でヒープを確保しない。`g` の型は `std::function<int(int)>` で、ヒープを確保し、呼び出しは間接呼び出しになる

## (2)

この処理系では次が成り立つ。

- `std::vector<int>::size()` の戻り値の型は、64ビットの符号なし整数である
- `unsigned` は 32ビットの符号なし整数である
- 64ビット符号なし整数から 32ビット符号なし整数への変換は暗黙に行われ、その初期化は適格である
- 変換後の値は、元の値を 4294967296（2の32乗）で割った余りである。値 4294967296 の変換結果は 0 である
- `auto` は初期化子を別の型へ変換せず、初期化子の式の型を変数の型にする

`v` は `std::vector<int>` であり、`v.size()` の値は 4294967296 である。

```cpp
unsigned sz = v.size();
auto n = v.size();
```

`sz` と `n` について最も適切なものはどれか。

A. `sz` の値は 0 である。`n` の型は `size()` の戻り値の型で、値は 4294967296 である

B. ビット幅が異なるため、`sz` の初期化も `n` の初期化も不適格である

C. `n` の型は `unsigned` になり、値は 0 である

D. `sz` と `n` の型は同じで、値はどちらも 4294967296 である

## (3)

`std::map<std::string, int>` の要素型は `std::pair<const std::string, int>` である。これは `std::pair<std::string, int>` とは別の型であり、キーは `const std::string` である。

範囲 for は、各要素 `e` についてループ変数を `e` で初期化する。この問では次を仮定する。

- 参照の型と `e` の型が異なり、変換コンストラクタで一時オブジェクトを作れるときは、一時オブジェクトが作られ、参照はそれに束縛される
- `std::pair<const std::string, int>` から `std::pair<std::string, int>` へのその変換は可能で、キーの `std::string` をコピーする。この初期化は適格である
- `const auto&` は要素型そのものへの const 参照になり、上記の変換は行わない
- コンパイラの最適化は考えない

```cpp
template<typename T>
void use(const T&);

std::map<std::string, int> m{ {"k", 1} };

for (const std::pair<std::string, int>& p : m) {
    use(p);
}
for (const auto& q : m) {
    use(q);
}
```

`use` の定義は別の場所にあり、引数を読む。`p` と `q` について最も適切なものはどれか。

A. `p` も `q` も、`m` の要素そのものを参照する。キーのコピーは起きない

B. `q` は一時オブジェクトを参照する。`p` は要素そのものを参照する

C. `p` は、キーの文字列をコピーして作った一時オブジェクトを参照する。`q` は要素そのものを参照する

D. `p` の初期化は型が一致しないため不適格である。`q` だけが適格で、要素そのものを参照する

## (4)

変更の前、`compute()` の戻り値の型は `int` である。変更の後、戻り値の型は `long` である。

この問では次を仮定する。

- `long` から `int` への暗黙変換があり、`int` 型の変数を `long` の戻り値で初期化する宣言は適格である
- `auto` は初期化子を別の型へ変換せず、初期化子の式の型を変数の型にする
- 下の変数宣言は書き換えず、再コンパイルだけを行う

```cpp
int x = compute();
auto y = compute();
```

再コンパイルの後の状態として最も適切なものはどれか。

A. `x` と `y` の型はどちらも `long` になる

B. `x` の型は `int` のままで、戻り値は `int` へ変換される。`y` の型は `long` になり、`y` の宣言を書き換える必要はない

C. `y` の型は、変更前に推論された `int` のままである。`long` にするには宣言を `long y` に書き換える必要がある

D. `x` の初期化も `y` の初期化も不適格になり、両方の宣言を書き換えないと再コンパイルできない
